# 全领域工程优化评测结果

模型：Qwen3.5-9B；每组 4 种方法、2 个随机种子。下表均为完整评测结果，先按实例计算指标再平均。

## 方法与指标

- 基线：原任务提示 + 历史记录，要求避免重复。
- 固定修复：上一轮错误时提供观察约束反馈，否则继续普通探索。
- 随机策略：随机选择普通探索、错误修复或结构探索。
- UCB：根据“找到一个此前未发现的正确候选”获得的奖励分配上述动作。
- VR 是正确生成比例；RR 是正确解空间覆盖率（主要指标）；NR 是不同可解析/空间内候选数除以请求次数，并不保证候选正确。

## 四种策略如何运行？

这些方法都不训练或修改模型权重，而是在每次调用前决定如何组织提示。每个实例独立运行，模型每次只生成一个候选答案。

| 策略 | 简要思路 | 每一轮的操作 | 用来验证什么 |
|---|---|---|---|
| 基线 baseline | 持续使用原始生成方式 | 给出观察和历史候选，要求再生成一个不同的答案；检查结果，但不把具体错误加入下一轮提示 | 作为同预算对照 |
| 固定修复 repair_only | 出错就纠正 | 上一轮错误时，附上上一条响应和错误反馈；否则使用原始提示继续探索 | 仅加入反馈是否已经足够 |
| 随机策略 random | 随机混合多种生成方式 | 在当前可用的普通探索、修复、结构探索中等概率选一个 | 收益是否只来自增加提示种类 |
| UCB 自适应 | 根据实际收益分配生成方式 | 优先尝试尚未使用的可用动作；之后结合平均奖励和探索加分选择动作，平分时随机选择 | 自适应分配调用是否优于随机或固定规则 |

所有方法都保留已解析候选的历史，而不是每次重新从零提问。修复动作仅在**上一轮有错误**时可用；重复但正确的答案不会触发修复。随机策略和 UCB 在没有错误时只能选择普通探索或结构探索。

UCB 的奖励为：找到一个本实例内**此前没有发现的正确候选**记 1 分，错误或重复记 0 分。每个实例重置动作统计，不跨实例学习，也不更新模型参数。当前实现的动作得分为 `平均奖励 + sqrt(2 × ln(总调用数 + 1) / 该动作调用数)`，探索系数为 1。

### 不同领域的三个动作

| 领域 | 普通探索 | 错误修复 | 结构探索 |
|---|---|---|---|
| 因果图 n=4 | 根据干预观察生成 A、B、C、D 上的 DAG，并避免重复图 | 指出某次干预下，哪个节点应受影响或不受影响，却被图预测错了；解析失败时提示合法 DAG 格式 | 从 0～6 中随机选边数，要求尝试恰好具有该边数的 DAG |
| 3D 重建 | 根据俯视投影生成逐层积木结构，并避免重复结构 | 指出投影格子不符、悬空、网格尺寸错误、空底层或高度超限等问题 | 从 1～3 中随机选非空层数，要求尝试恰好具有该层数的结构 |
| Boolean Basic | 根据输入输出观察生成表达式；允许 AND、OR | 指出哪条输入的预测输出错误；也检查变量、运算符、常量和深度约束 | 从 AND、OR 中随机选一个，要求它作为表达式最外层运算符 |
| Boolean Extended | 同上，允许 AND、OR、NOT | 同上 | 从 AND、OR、NOT 中随机选择最外层运算符 |
| Boolean Full | 同上，允许 AND、OR、NOT、NOR | 同上；NOR 按数据生成规则作为一层基本运算 | 从 AND、OR、NOT、NOR 中随机选择最外层运算符 |

结构探索是提示方向，不是新增的评分条件。如果指定方向不可行，提示允许模型返回其他有效且不重复的答案；最终仍按原任务的观察和约束判断正确性。布尔三组都使用本次主套件的最大深度 2。

### 一次完整评测的过程

1. 读入一个实例的观察与公开约束，初始化空历史；UCB 同时初始化动作计数和奖励。
2. 根据所用策略选择动作，构造“原任务提示 + 历史候选”，必要时加入错误反馈或结构探索方向。
3. 调用同一个 9B 模型生成一个候选；每轮只调用一次，不因答案错误而额外重试。
4. 解析并检查候选，记录正确性、重复性、响应和 token 用量。修复反馈仅来自观察与公开约束。
5. 记录历史，计算“新且正确”的奖励；UCB 更新所选动作的统计，然后进入下一轮。
6. 预算耗尽后，再与标准解集匹配，计算 RR 等指标。各方法使用相同的实例和请求预算。

### 三个直观例子

- **因果图**：观察要求干预 A 后 B 受影响，但候选图中 A 无法到达 B。修复提示会指出“B 应为 1，但该图预测为 0”；模型再修改图，检查器不会直接给它标准图。
- **3D**：俯视图要求某格有积木，但候选的所有层在该格都为空。修复提示会指出该格投影应为 1；结构探索则可能另行要求尝试 2 个非空层，鼓励改变高度组合。
- **布尔逻辑**：观察为 `(x=1, y=0) → 1`，候选为 `x AND y`，预测得到 0。修复提示会指出这条矛盾；结构探索则可能要求最外层使用 OR。生成答案后仍须检查所有观察。

同一个例子中，基线总是继续普通探索；固定修复下一轮一定处理已发现的错误；随机策略可能选择修复，也可能探索；UCB 则根据本实例中各动作此前的收益与探索需要决定下一步。因此，四种方法比较的是**如何使用有限调用预算**，并非模型本身不同。

## 评测边界与可复现性

- 因果使用原有 200 个测试实例，预算为正确图数的 2 倍；其他领域使用主套件全部实例，预算为正确候选数的 1 倍。各方法在同一领域内请求预算相同，token 成本并不相同。
- 因果实验使用 4 并发，其他领域使用 32 并发；不跨实验比较墙钟速度。并发可能影响服务端数值可复现性。
- 跨领域小批次使用每组 2 个实例、每任务 3 次请求，只检查解析与运行健康，未据此调整方法；这些实例包含在全量评测中，所以不宣称全新、完全未接触的测试集。
- 反馈只使用观察与公开约束。真实解集在生成完成后用于评分，解集大小仅按基准协议用于确定预算。
- Boolean 保留上游 mechanistic key 的结构等价规则；统一修正验证器对 NOT+OR 的错误拒绝，并将 Full 的 NOR 按数据生成规则计为一层。修正应用于全部四组方法，因此新基线不能直接与旧验证器结果混用。
- 3D 统一检查投影、支撑、网格尺寸、0/1 值和最大高度；所有 4,254 个跨领域标准答案都通过了适配器验证。
- 每个实例先平均两个种子，再按实例 bootstrap 10,000 次。区间为描述性结果，未做跨领域、多对照的多重比较校正。
- 原因果正式评测和跨领域评测独立保存冻结配置、逐次响应、请求日志、环境及汇总记录。
