## 3. 这些数字怎么读（限制，必须写进报告）

- **不能和论文逐格对比。** 论文 Causal 按节点数分 Level（4/5/6）；我们是 n=4 数据集内取 `|H_O|≥8`，比论文 Level 1 难。论文 3D 用不同数量的 top-down 视图分难度；我们的 `g3_h3_b3` 是单一 top view、block 数 ≤3。Boolean 的算子集对得上（basic=AND/OR，extended=+NOT，full=+NOR），深度固定 2。
- **只做组内比较**：不同模型/配置必须同数据、同子集、同预算、同 prompt。
- **预算**：causal 用上游默认 2.0×（论文与代码默认一致）；3D/Boolean 1.0×。不同预算下的 RR 不可比。
- **旧结果不可混用**：`results/legacy/local_*` 是 2026-11-17 的早期跑，causal 是随机 200 个实例（含 46 个 `|H_O|=1`，中位数 3），与现在的 `|H_O|≥8` 子集（中位数 12）完全不同；27B 同一批 30 个 3D 实例重跑也有 +7 个点左右（70.5/67.2/45.4 → 73.5/70.7/52.3），因为 27B 服务配置变过。旧表只能当历史记录。
- **27B 在 Boolean 上输出变长**（full 档 148 token/query，旧的 39）：长度 >60 字符的输出，旧跑 90/975 条，新跑 77/975 条，条数没涨但总 token 涨了。是服务端 max_tokens / 模板改动，不是模型行为突变。成本统计不能跨版本比。

## 4. 失败模式分解（同一批 JSON，按 query 计数）

`invalid` = 解析成功但在观测上不一致（含 Boolean 越界，官方口径）；`validNotNew` = 合法但与已生成假设重复；`new` = 合法且新（接近 RR 的分子）。

| 设置 | 模型 | invalid | validNotNew | new |
|---|---|---|---|---|
| causal n4 | 9B | 61.6 | 35.3 | 3.2 |
| causal n4 | 27B | 52.9 | 33.7 | 10.1 |
| 3D | 9B | 47.7 | 34.5 | 17.8 |
| 3D | 27B | 31.2 | 24.1 | 44.5 |
| boolean extended | 9B | 27.5 | 61.4 | 11.2 |
| boolean extended | 27B | 52.2 | 17.3 | 30.6 |
| boolean full | 9B | 33.1 | 61.2 | 5.6 |
| boolean full | 27B | 47.8 | 33.7 | 18.5 |

结论：

1. **无效假设是最大的单一损失来源**（causal 52–62%，boolean extended/full 27–52%）。"前沿模型 VR 饱和"不适用于本地基线。
2. 9B 在 Boolean 上主要是**重复**（61%），27B 主要是**无效**（48–52%）。
3. 解析失败可忽略（≤3.3%，且集中在 causal）。

## 5. 论文已做的干预（事实记录）

- 温度 0.2–1.0、top-p、预算加到 3×|H_O| 都不改善 RR（Table 6）。
- complexity-stratified decoding 在 4/7 模型上有正收益，但 Simple RR 普遍下降，DeepSeek-R1 −19.2；净收益不稳定。
- memory-based rejection / ensembling / diversity prompt 论文未给数字。
